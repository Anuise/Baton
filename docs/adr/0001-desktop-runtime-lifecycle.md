# ADR-0001：桌面與 Runtime 生命週期政策

- 來源識別：DR-20261021-01
- 狀態：已確認（使用者核准，2026-10-21）；Windows 程序控制與恢復為 Validation Required，尚未驗證
- 來源：[issue #3](https://github.com/Anuise/issue-orchestrator/issues/3) §17 DR-20261021-01；§1.2、§12.1、§14、§15.3
- Spec 對應：[spec.md](../../.scratch/platform-rebuild-v1/spec.md) 的 D-11（完全退出寬限期）、D-19（安裝與更新）

## 背景

使用者需要讓長時間工作在視窗關閉後繼續，同時保有「我要停就停」的明確手段。若桌面視窗與工作程序綁在一起，關窗就中斷工作；若沒有明確的停止意圖，Windows 更新重開機等事件會被誤當成使用者想繼續。自動續跑也不能是一個全域開關，否則一個 Workspace 的設定會連帶啟動其他工作。

## 決策

採 B＋E2＋R3＋S2：

- 同一次 Windows 使用者登入期間，Runtime 獨立於桌面視窗在背景執行；關閉視窗後工作繼續，重新開啟連回同一個 Runtime，不建立第二個控制平面。
- 「完全退出」採限時受控停止：先持久化停止意圖，停止新派工、建立交接 successor 與啟動重試，再要求現有 Controller／Worker 於寬限期內保存進度並停止，逾時終止平台管理的程序樹。停止不依賴最後一次模型回應。
- 主動完全退出後再次開啟，先核對既存程序、成果與外部操作，再依「各 Workspace」的自動續跑設定決定恢復或等待使用者按「繼續工作」；設定預設關閉，變更不立即啟停目前工作。
- 自動續跑不構成新的操作授權，不繞過待裁定、授權不足或未知副作用的阻擋。

Spec 補充（AI 暫定，待使用者確認）：寬限期具體值於 spec D-11 暫定為 30 秒受控停止 + 10 秒強制終止確認，總上限 40 秒；issue 明載具體秒數尚未決定，須以 Windows 原生測試確認。

## 替代方案

- 隨視窗退出：增加工作中斷。
- Windows 系統服務：增加部署複雜度。
- 等待全部工作完成才退出：無限等待。
- 立即強制停止：增加恢復負擔。
- 固定手動或固定自動續跑：缺乏彈性。
- 全域自動續跑開關：影響範圍過大。

## 後果

- 使用者必須被告知「關窗不等於停止」，系統匣要有明確的「完全退出」入口。
- 排程、Outbox 與 supervisor 啟動路徑都必須檢查停止意圖，不能只停排程器。
- 終止本機程序不等於取消已送出的外部操作，結果仍依查證規則處理。
- 後續 ADR 在此基礎上補足：崩潰恢復（[ADR-0005](0005-runtime-crash-recovery.md)）、監護（[ADR-0006](0006-runtime-guardian.md)）、跨登入啟動（[ADR-0007](0007-cross-login-startup.md)）；這些不取代本決策。

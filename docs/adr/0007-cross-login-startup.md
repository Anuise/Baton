# ADR-0007：跨登入啟動、Workspace 續跑與完全退出優先序

- 來源識別：DR-20261021-07
- 狀態：已確認（使用者核准，2026-10-21）；Windows 實作為 Validation Required，尚未驗證
- 來源：[issue #3](https://github.com/Anuise/issue-orchestrator/issues/3) §17 DR-20261021-07；§1.2、§11.2、§11.4、§12.7、§15.9
- Spec 對應：[spec.md](../../.scratch/platform-rebuild-v1/spec.md) 的 D-25（跨登入啟動入口）、User Stories 17、82–83

## 背景

使用者希望重新開機後長任務能無人值守地恢復，但又要保證「完全退出」的停止效力不會被 Windows 更新重開機或重新登入間接解除。「平台啟動」與「工作執行」是兩種不同的意圖，不應共用同一個開關。

## 決策

採 B＋B2＋S1：

- 「登入時自動啟動」是目前 Windows 使用者層級的選項，預設關閉。每個 Workspace 另有「跨登入自動續跑」，預設關閉，與 [ADR-0001](0001-desktop-runtime-lifecycle.md) 的「主動退出後續跑」分開。
- 兩項偏好只決定後續啟動與恢復，不立即啟停目前的工作，也不解除既有的停止或故障阻擋；登入自啟動不構成工作授權。
- 一般跨登入啟動先核對資料、程序、成果、外部操作與恢復紀錄，再依 Workspace 設定續跑或等待人工；只延續原本允許執行且通過檢查的工作。
- **完全退出優先（S1）**：停止意圖跨登入保留。下次登入的啟動入口檢查後，受抑制時不啟動背景 Runtime、監護或工作；保留原自啟動偏好，停止抑制另存。只有使用者手動開 App 才進入 ADR-0001 的流程，不得改用跨登入設定繞過。
- 重新登入不清除恢復事件、次數、退避與額度用盡阻擋；啟動來源或停止意圖無法核對時不自動續跑。

Spec 補充（AI 暫定，待使用者確認）：D-25 暫定以 HKCU Run 登錄機碼啟動輕量 launcher，並把停止意圖另以原子寫入的生命週期檔鏡像，兩者不一致時取較保守者（視為停止）。

## 替代方案

- 跨登入一律人工繼續：增加停滯。
- 共用 ADR-0001 的開關：混合兩種意圖。
- 只手動啟動：無法無人值守恢復。
- 登入自啟動預設開啟：增加意外背景執行。
- 停止意圖只限本次登入：完全退出後下次又會自動復工。

## 後果

- 增加設定、啟動整合與驗收成本。
- 完全退出後必須手動開 App；忘記時工作持續停止。
- 不承諾登入前、登出期間或關機時持續工作，不提供系統服務模式。
- 指定時段、延遲啟動與一次性略過自啟動留待後續。

# ADR-0003：Workspace 授權與多帳號版本化設定

- 來源識別：DR-20261021-03
- 狀態：已確認（使用者核准，2026-10-21）；原生整合與 Windows 實作為 Validation Required，尚未驗證
- 來源：[issue #3](https://github.com/Anuise/issue-orchestrator/issues/3) §17 DR-20261021-03；§2.2、§3.4、§6.1、§6.2、§9.2、§12.3、§15.5
- Spec 對應：[spec.md](../../.scratch/platform-rebuild-v1/spec.md) 的 D-08（權限轉接）、D-09（設定版本固定）、User Stories 4–6、10–17

## 背景

平台要支援背景自主工作，但每一步都問使用者會打斷工作，全面放行又權限過大。多個帳號各有獨立的登入與 Session，共用設定若即時熱重載，會與「已准入 Run 沿用舊授權」互相衝突。

## 決策

採 B＋B1-b＋E1＋R1-a＋I2＋P3＋S3：

- **授權**：Workspace 共用「能力＋目標資源＋限制條件」的範圍授權；範圍內預先授權，例外送人工裁定。Goal／Task／Stage 只能引用並收窄，不能放寬。
- **E1**：例外批准只綁定單一邏輯操作（穩定識別、目標資源、重要參數、要求雜湊、成果版本），不增加共用權限，完成後不能用於另一操作。介面區分「允許本次操作」與「修改 Workspace 授權」。
- **R1-a**：授權更新與啟動准入依持久化順序判定。撤銷前已准入的 Run 沿用舊授權與設定版本；尚未准入者、交接 successor 與恢復 Run 使用新版。已准入 Run 的撤權沒有固定完成時間，使用者可另行暫停或取消。
- **I2**：新 Workspace 提供可編輯的建議範本，使用者確認並保存後才生效；選取目錄不等於授權。
- **P3**：可信專案開發範本涵蓋編輯、指定環境建置與測試、指定來源的專案依賴安裝，並揭露「專案與第三方依賴程式以使用者 Windows 身分執行」的風險。管理員／全域安裝、遠端寫入、部署、對外發訊、付費與正式資料操作須各自授權。
- **S3**：各帳號以各自的 `CLAUDE_CONFIG_DIR` 管理原生登入與 Session，不共用整個 Profile；共同設定從使用者既有設定匯入、版本化，採用更新後建立新版本供新准入的 Run 使用，不改寫使用者平常手動使用的設定，也不複製其他帳號的登入資料。

Spec 補充（AI 暫定，待使用者確認）：D-09 規定每個 Run 啟動時把設定快照寫成該 Run 專屬的唯讀設定檔；D-08 規定 Worker 以非互動權限模式執行並經 permission-prompt 工具轉接。具體 CLI 參數與最低版本為 Validation Required，無法維持契約時阻擋，不改為全面放行。

## 替代方案

- 逐次確認：增加人工打斷。
- 全面放行：權限過大。
- Goal／Task 逐項授權：增加動態拆工負擔。
- Task 期間例外或批准即擴權：效力歧義。
- 撤銷時受控停止或強停整個 Workspace：增加中斷，未作為一般撤銷政策。
- 撤銷前全部 queued Run 沿用舊權限：生效過遲。
- 空白設定：增加首次使用負擔。
- 只編輯或不安裝依賴：容易阻擋完整開發。
- 設定首次複製後各自演變：容易分歧；即時共用熱重載：與 R1-a 衝突。

## 後果

- 不保證攔截可信專案與依賴程式的全部內部副作用；Profile 目錄不構成 OS 安全隔離。
- Windows 原生憑證依實際檔案機制管理，不宣稱已進入系統憑證儲存。
- 直接熱重載共用授權並同時承諾 R1-a 是已確認的衝突，S3 的實作必須避免。
- 設定來源、權限介面或管理政策不相容時，保存阻擋原因，不靜默放寬權限。

## 修訂紀錄

### 2026-10-27：決策權限表改為使用者可自由設定（含放寬）

- 來源：使用者決定「裁定的部分決策權限表要全部都可以讓我手動編輯，沒有甚麼是不可以放寬的」。
- 變更：決策權限表（spec D-15，`baton_domain::authority`）原本只允許 Workspace 把內建「可自主處理」的事項收窄為「必須送裁定」，放寬或調整「只能人工發起」的事項一律拒絕。現在每個事項都可以由使用者設為「可自主處理／必須送裁定／只能人工發起」任一等級；生效等級＝使用者設定，未設定時＝內建。內建等級只作為預設值與介面上的參考。
- 不變：本 ADR 的 Workspace 授權（能力＋目標資源＋限制條件）規則不變，Goal／Task／Stage 仍只能引用並收窄；權限表仍以 revision 樂觀鎖保護、取代式更新。
- 資料：`decision_authority_policy` 改存 `overrides`（只記與內建不同的事項）；舊資料的 `narrowed` 轉成 `requires_decision`，生效等級與改版前相同。

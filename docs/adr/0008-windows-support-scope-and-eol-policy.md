# ADR-0008：第一版 Windows 支援範圍與版本退場政策

- 來源識別：DR-20261021-08
- 狀態：已確認（使用者核准，2026-10-21）；實作尚未驗證
- 來源：[issue #3](https://github.com/Anuise/issue-orchestrator/issues/3) §17 DR-20261021-08；§1.1、§1.2、§2.1、§13、§14、§15.10
- Spec 對應：[spec.md](../../.scratch/platform-rebuild-v1/spec.md) 的 User Stories 8–9、「首次啟動與平台」

## 背景

支援的平台範圍決定驗收成本。支援過多組合會稀釋驗證；只支援最新版本又增加升級門檻。同時，長任務不應因為作業系統過了支援期限就被強制中斷。

## 決策

採 A＋A1＋E1＋L1：

- 第一版正式支援 Windows 11 x64 Home／Pro；初始驗證目標為 25H2 與 26H2，新功能版本驗證後才納入。Claude Code 只支援 Windows 原生執行，不支援 WSL 執行環境。
- 平台支援與實際 Claude Code 及必要依賴的相容性須同時滿足；診斷與驗收記錄 OS 功能版本、build、版本別、原生架構、應用程式、CLI 與依賴版本。可編譯不代表已通過執行驗證。
- 初始四種組合（兩個版本 × Home／Pro）須完成驗收，才可對外宣稱正式支援。
- Windows 10、Server、ARM64 與 ARM 上的 x64 模擬、Home／Pro 以外的版本別，不提供正式支援（顯示為非正式支援但不阻擋使用）。
- 已認證版本隨 Microsoft 對相應功能版本結束支援而退出正式支援，採 L1：顯示警告，但不單憑日期停止 Run，也不禁止新派工、交接或恢復。

## 替代方案

- 加入 ARM64 或 Windows 10：增加驗收組合。
- 只支援最新版本：增加升級門檻。
- 發布前才選版本：延後風險發現。
- 企業版本或實驗性支援：增加政策與客服成本。
- 到期後禁止新 Run：會阻擋交接與恢復。

## 後果

- 客群縮小，四種組合的驗收成本不可省略。
- 使用者可能在缺少 OS 安全更新的環境繼續執行（L1 接受此風險），平台不承諾持續相容。
- 到期不刪資料、不強制退出 App，保留診斷、成果查看與備份／匯出入口。
- 既有的依賴、安全、授權、設定、憑證與 writer 檢查仍然有效，不因 L1 而繞過。
- 若發布時版本已到期，須另行審查。

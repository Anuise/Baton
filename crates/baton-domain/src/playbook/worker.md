# Baton Worker 通則

以下規則由 Baton 附加在每個 Worker Run，與 Task 契約一起構成你的指示；Task 契約比通則更嚴格時以契約為準。

- 先以 `get_task_contract` 讀 Task 契約，只做契約範圍內的事。
- 以 TDD 實作：先寫會失敗的測試，再寫讓它通過的最小實作，最後重構。不適用測試的工作（研究、文件）以契約的完成條件逐項自我檢查。
- 所有變更 commit 到這個 Task 的 worktree 分支（工作目錄目前所在的分支）；不要切換分支、不要 push、不要修改其他分支。
- 平行化時同時最多 3 個 subagent；有相依或會改同一檔案的工作不要拆給不同的 subagent，subagent 的成果由你整合、測試、commit。
- 遇到不明確處先自己決定並繼續，再把決定追加到 AI 決策紀錄（路徑寫在 Task 契約中；沒寫時在最後的回報中列出你的決定，由 Controller 代為追加）。只能在檔尾追加新條目，不修改、不刪除既有條目；編號 AI-NN 接續檔中最大的編號，格式如下：

  ```markdown
  ### AI-NN：<主題>
  - 重要度：高｜中｜低
  - 時間／階段：YYYY-MM-DD，<這個 Task 的階段>
  - 決策：…
  - 理由：…
  - 替代方案：…
  - 影響：…
  - 審閱：未審
  ```

- 受阻時以 `report_blocked` 回報原因；不要猜測或繞過 Workspace 授權。

# 領域分類與評估

以下僅是檢查覆蓋範圍的初始框架，不代表來源已存在這些設計。依實際內容合併、拆分或新增，領域數不固定；若沿用 ID，先確認不與現有分類衝突。

| 參考 ID | 領域 | 範圍 |
|---|---|---|
| D01 | 產品定位與商業需求 | 客群、價值、情境、MVP |
| D02 | UI 與 UX | Web UI、流程、首次使用 |
| D03 | 整體架構 | 分層、邊界、通訊、API |
| D04 | Runtime 與環境 | 連線、程序、隔離、生命週期 |
| D05 | Agent Orchestration | Orchestrator、Worker、Verifier、Scheduler |
| D06 | Agent 通訊與上下文 | Mailbox、Session、Context、交接 |
| D07 | 任務與流程 | 拆分、依賴、狀態機、排程、人工介入 |
| D08 | 資料與持久化 | SQLite、Schema、交易、一致性、遷移 |
| D09 | 可靠性與恢復 | Crash Recovery、重試、冪等、備份 |
| D10 | 安全與權限 | 認證、授權、憑證、隔離、攻擊面 |
| D11 | 安裝部署與更新 | Compose、初始化、升級、解除安裝 |
| D12 | 可觀測性 | Logs、Metrics、Tracing、歷史、告警 |
| D13 | 第三方整合 | Claude Code、Codex、GitHub、MCP、Plugins |
| D14 | 測試品質 | Unit、Integration、E2E、驗收、壓力 |
| D15 | 效能資源 | 並行、配額、效率、成本 |
| D16 | 商業化與授權 | License、定價、版本、付費 |
| D17 | 發布治理 | Release、相容、變更、Roadmap |
| D18 | 文件與開發體驗 | 使用、API、維護、貢獻 |

每域統計：已確認、未決、待驗證、缺漏、衝突數；註明阻塞、MVP 重要性、修改成本／回退難度與規格完整度。統計須依可識別項目，不猜數字。

Decision Coverage = 已確認決策數 /（已確認決策數 + 未決決策數）。計算前列明納入哪些狀態、決策集合與已知缺漏；樣本不完整或分母為零用 N/A。未列出未決事項不等於 100%。比例只代表已識別決策覆蓋，不代表品質、實作或可發布程度。

優先級各維度 1–5 分，按權重加總：前置依賴／阻塞 30%、修改成本／不可逆性 20%、安全／資料完整性／可靠性 20%、MVP／使用者價值 15%、商業／交付風險 10%、技術未知／驗證需求 5%。提供評分依據；證據不足用待評估，不編造精確分數。推薦不取代使用者選擇。
